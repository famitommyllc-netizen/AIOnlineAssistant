# UI Consistency Standards (Latest)
- Updated: 2026-03-30 09:06:59 JST
- Scope: `apps/erp/src/gas/*.html`, `apps/erp/src/gas/style.css.html`
- Purpose: 画面ごとの見た目・入力体験の揺れをなくし、修正時の再発を防ぐ。

## 1. 統一対象（必須）
- 文字サイズ（見出し/本文/補助文/テーブル）
- フォームサイズ（input/select/textarea/buttonの高さ・余白）
- 形状ルール（角丸、＋ボタン、削除ボタン）
- 日付入力方式（入力フォーマット、表示、補助UI）
- 画面密度（セクション余白、行高、モバイル時の縮尺）

## 2. タイポグラフィ規約
- 基本は `style.css.html` のCSS変数を単一ソースにする。
- 画面個別でサイズを変える場合は、必ず `body.<page-layout>` 配下の上書きに限定する。
- 同一意味のテキストは同一トークンを使う。
- 例:
- 見出し: `--list-header-font-size`
- セル本文: `--list-cell-font-size`
- ラベル: `--list-label-font-size`
- 補助文: `--list-helper-font-size`

## 3. フォーム規約
- フォーム高さは `min-height` を基準にそろえる。
- `input/select/textarea` と `button` のサイズは別々にトークン化し、固定運用する。
- 画面個別調整は「サイズ差分のみ」を持つ（色や構造まで混ぜない）。

## 4. 形状規約
- 通常ボタン: 角丸矩形（丸ボタン禁止）。
- `＋` ボタン: 例外として「追加アクション」用途のみ丸ボタン可。
- `＋` ボタンを丸にする場合は以下を満たす:
- ラベルは `aria-label` を必須
- 直径・色・フォントサイズをトークン化
- 同一画面内で形状を混在させない（丸なら全追加ボタンを丸で統一）

## 5. 日付入力規約（固定）
- 仕入日入力は `YYYYMMDD` を正規入力形式とする。
- 実装は以下の組み合わせを維持する。
- 表示/入力: テキスト入力（数字8桁）
- 補助: date picker連携（内部でISO変換）
- Bの入力オーバーレイでは、日付入力欄の右端に「選択」ボタンとカレンダーアイコンを付ける。
- 正規化関数を必ず通す。
- `normalizeDateDigits_`
- `digitsToIsoDate_`
- `isoDateToDigits_`

## 6. CSS配置規約（今回の再発防止）
- 原則: 内部CSS禁止。すべて `style.css.html` に集約。
- 例外: なし（将来やむを得ない場合は、例外理由をこのdocsへ追記）。
- ページ固有スタイルは `style.css.html` 内でセクションコメントを付ける。
- 例: `/* EntryFormB: ... */`

## 7. 変更手順（必須フロー）
1. 修正前に本ドキュメントとチェックリストを読む。
2. 変更対象が統一対象に触れるか判定する。
3. 触れる場合、先にトークン/規約を更新してから画面実装を変える。
4. A/B/通常画面で見た目差分を確認する。
5. 変更後にチェックリストを再確認し、差分説明を残す。

## 8. レビュー観点
- 同じ意味のUIが別サイズ・別形状になっていないか
- ページ内だけで成立する“場当たりstyle”が増えていないか
- 日付入力のフォーマットが画面ごとに変わっていないか
- モバイル（<=768px）でタップ領域が縮んでいないか

## 9. 運用ルール
- このファイルを「統一ルールの正本」とする。
- ルール変更時は必ず更新日を変更し、`docs_index_latest.md` を更新する。
- 画面改修時は、最終報告にこのファイル準拠可否を明記する。
