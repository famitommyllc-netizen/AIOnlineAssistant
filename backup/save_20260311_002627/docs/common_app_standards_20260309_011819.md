# Common App Standards
- Saved At: 2026-03-09 01:38:14 JST
- Purpose: 次アプリでも同一デザイン・同一操作性を再利用する共通仕様

## 1. ヘッダー共通
- [1] 同一レイヤー横並び: MENU / ページボタン / ×。
- [2] × は右端真円固定。
- [3] サブ画面の×は当該アプリのホームへ戻る。
- [4] アプリホームの×は連携元（秘書チャット）へ戻る（将来含む）。

## 2. チャットレイアウト共通
- [5] 固定ヘッダー + 固定フッター + 中央スクロールのみ。
- [6] 中央エリアをさらに内側カードで二重に囲まない。
- [7] メタ情報はバブル外に表示。
- [8] 入力欄は1行で送信ボタン同列。

## 3. モードUI共通
- [9] モード終了ボタンは入力欄の直上フロート。
- [10] 通常モードではモード終了UIを非表示。

## 4. 位置変更モード共通
- [11] モード中は入力不可、移動操作に集中。
- [12] Row左側に縦3点ハンドル。
- [13] Row移動は長押しドラッグ。
- [14] Section移動は上下矢印、端では非活性。
- [15] iOS長押し選択メニューは抑止。

## 5. 通知UX共通
- [16] alert/confirm は使わずアプリ内通知へ置換。
- [17] 通知位置は画面中央、視認性を優先。
- [18] 実行系ボタン（保存・更新・計算など）は必ず結果通知を返す。

## 6. 履歴軽量化共通
- [19] 当日表示は軽量化、過去は日次アーカイブで分離。
- [20] 保存済み痕跡と読込導線を残す。
- [21] 上スクロール時の段階読込を標準方式とする。

## 7. データ/設定共通
- [22] UI並び順は設定として保存し、リロード後に再現。
- [23] 設定は画面namespaceで保持（例: calculators.profit.ui）。

## 8. 回帰防止
- [24] KPIや主要rowの高さ・1row表示はロックCSSで保護。
- [25] 重要UI変更は docs と change_log を同時更新。

## 9. 1row優先ルール
- [26] 基本方針として、情報が1行で成立するUIは1rowで設計する。
- [27] モード表示は「モード名 + モード終了ボタン」を常に同一1rowで表示する。
- [28] 1rowが崩れる変更は原則禁止し、必要時は要件合意後に実施する。
